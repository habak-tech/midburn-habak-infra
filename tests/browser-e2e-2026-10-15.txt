Environment and method
Real desktop Chrome on ori-lp, attached through Playwright CLI/CDP; no headless
substitute, mocked API, or direct database seeding. All application data creation
and mutations used actual UI controls. Two read-only fetches inside the browser
additionally verified server-side 403 responses. Source inspection and independent
PDF tools were used to explain findings, not as substitutes for UI tests.
Primary origin: https://192.168.50.218:8543
Second origin: https://192.168.122.60:8543
Accounts: admin followed by volunteer; final additional admin checks on second IP.
Test marker: E2E-1015. All contacts, equipment transactions, and procedures fictional.

Result
Main admin setup and volunteer operational workflows passed. The suite is not
fully green: exports omit updates, contextual AI retrieval missed an answer, and
one PDF fixture failed ingestion despite successful independent text extraction.
No application code was changed during this testing task.

Confirmed findings

1. OPS EXPORT DATA LOSS — both CSV and PDF omit saved event updates.
   Reproduction: create an event, add an update, close it, select Closed events,
   export CSV/PDF. Event detail shows the update; both exports say no updates.
   Test event ID prefix: 5adbcf72.
   Evidence: artifacts/browser-e2e-2026-10-15/events.csv and events-export.png.
   The screenshot volunteer-ops-complete.png shows the saved updates (a second
   completion update was added after the original exports).
   Source: ../midburn-ops-log/src/pages/Index.tsx:32 initializes eventUpdatesMap
   to an empty object and passes it into EventsExplorer/ExportDialog. Both
   exporters read this empty map. Files download and PDF renders, but data is lost.

2. AI CONTEXTUAL RETRIEVAL LIMITATION — follow-up misses indexed information.
   Uploaded E2E-1015-test-procedure.txt defines Purple Lantern / פנס סגול,
   fictional code 7419, and completion steps. Explicit question about station/code
   succeeds. Follow-up "ומה צריך לעשות בסיום הבדיקה הזאת?" returns the no-procedure
   fallback. Explicitly naming E2E-1015-test-procedure.txt and Purple Lantern in
   the next question succeeds and says to mark the test complete.
   Conversation retained for reproduction. One observed case, not a statistical
   evaluation of model quality. Answers named the document in prose; no clickable
   source citation control was observed in these responses.

3. PDF COMPATIBILITY EDGE CASE.
   The small PDF preserved as artifacts/browser-e2e-2026-10-15/
   E2E-1015-delete-test.pdf fails AI upload with HTTP 500 / "bad XRef entry".
   Local pdfinfo reports a valid one-page PDF 1.4 without errors; pdftotext extracts
   both lines correctly. A second PDF generated with jsPDF ingests successfully,
   produces one chunk, and renders in Chrome's embedded PDF viewer.
   Thus PDF ingestion works generally, but this fixture exposes parser tolerance
   differences. Failed document is shown with a clear error in admin and excluded
   from the library. Successful Markdown in the same batch remained available.
   Failed record deleted via admin UI after recording evidence.

Expected behavior and usability notes
- Reopen is admin-only. Volunteer sees a Reopen button but receives the explicit
  "only an administrator can reopen a closed event" notification. Admin reopen
  succeeds. Initial apparent no-op was this restriction, not an update failure.
- Talkies over-allocation is intentionally informational. A third radio could be
  issued against a daily allocation of two. This matches the existing design:
  ../burn-talkies/docs/superpowers/specs/2026-08-22-postgresql-proxy-auth-design.md
  lines 141-142. All three radios were returned individually afterward.
- AI conversation history is shared across users. Volunteer can see previously
  existing admin conversation titles. The list and delete implementations describe
  shared conversations; this is not per-user private history. This run deleted
  only its own disposable conversation, not another user's conversation.
- AI and Talkies top links still target the LAN origin with absolute URLs, even
  when browsing the private IP. App routes and session domains work on both IPs,
  but these links switch origins (and therefore may switch authenticated accounts).
- Test certificates are self-signed. Chrome required accepting the known private-IP
  certificate on first use; certificate trust was not silently disabled globally.

Scope limits
This is a broad desktop Chrome functional acceptance run, not proof that every
possible input, browser, concurrency race, or load scenario works. Bulk delete-all
and reset-all destructive admin actions were inspected but not executed. Password
reset/email delivery, large-document limits, OCR/scanned PDFs, exhaustive advanced
filter combinations, pagination across many pages, mobile layouts, and offline/
recovery behavior were not exercised. No production records were used or restored.
